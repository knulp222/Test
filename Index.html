Aperçu Installation Structure Personnalisation Organisation Ressources

Aperçu rapide du dépôt

Handy est conçu comme une application front-end soignée et modulable. Avant de forker, prends une minute pour revoir les piliers qui structurent le projet original et note les points qui t'intéressent le plus pour ta variante.

Expérience utilisateur

Interface soignée, transitions fluides et forte attention à l'accessibilité. Le design repose sur un système de composants réutilisables qui facilitent les ajustements visuels rapides.

Composants modulaires

Le code sépare clairement les modules fonctionnels (navigation, scènes, interactions). Cela autorise des forks ciblés : tu peux modifier seulement la zone qui t'intéresse sans tout casser.

Animations et interactions

L'application s'appuie sur des animations CSS/JS légères pour donner vie à l'interface. Repère les hooks ou listeners déjà prévus afin de greffer tes propres effets.

Routage et état

La gestion d'état est centralisée (store ou contexte). Avant d'ajouter une fonctionnalité, vérifie où sont synchronisées les données pour rester cohérent avec l'application d'origine.

Décortiquer l'architecture

          

            Explore le dépôt pour identifier où vivent les composants que tu veux modifier. Ouvre les dossiers à la
            manière d'un explorateur de fichiers et prends des notes dans la zone prévue plus bas.
          

        

        

          Arborescence conseillée à inspecter en premier
          

            
src/

            
├─ assets/  → images, icônes, sons

            
├─ components/  → éléments UI réutilisables

            
├─ layouts/  → structures de page

            
├─ pages/  → vues principales

            
├─ hooks/  → logique partagée (state, effets)

            
└─ styles/  → variables, thèmes, mixins

          

        

        

          Points de vigilance
          

            ✔️ Cherche les fichiers de configuration (Vite, Webpack, ESLint) pour comprendre les alias.
            ✔️ Identifie les services API ou mocks dans src/services s'ils existent.
            ✔️ Note les dépendances critiques (animations, state management) avant de les remplacer.
